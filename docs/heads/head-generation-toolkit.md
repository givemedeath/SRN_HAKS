# Head generation toolkit: operator runbook v1

This is the fresh entry point for new heads. Historical runbooks remain research evidence; their donor coordinates and repair experiments are not defaults. The toolkit extracts the successful #73/#74 single-image route and retains attempt51 as the alternate multiview baseline. It produces review candidates, not automatic production approval.

## Choose the input route

| Route | Use | Geometry conditioning | Appearance conditioning | Camera |
|---|---|---|---|---|
| `pixal-single-v1` (default) | A design whose full hairstyle and accessories are unambiguous in one near-frontal angled image | One smooth clay image, native `Pixal3DConditioning`, single-image checkpoint | Matching detailed image on the exact saved shape | Reviewed horizontal MoGe estimate, shared between geometry and appearance |
| `pixal-multiview-v1` (alternate) | Complex rear hair, horns, tusks or cyberware that one image cannot establish | Four measured cardinal geometry images through `Pixal3DMultiViewConditioning`, **multiview checkpoint** | Detailed **front only**, through the same multiview conditioner/checkpoint, on the saved shape | Retained **20°** rig, 90° view spacing, common framing |

The alternate comes from corrected-input attempt51, which later reached an accepted in-game result after downstream repair. That baseline used **blank-orbit geometry references, not monochrome clay**. Reuse that preparation for the closest historical control; applying the newer smooth-clay preparation to multiview is a separate conditioning trial, not an already validated result. The example `frontClay`/other `Clay` roles name geometry-conditioning copies and can hold the baseline blank-orbit references. Attempt52 had duplicated accessories and is not the baseline. The later front/back experiments are not substituted for this four-view baseline. Multiview is an explicit operator choice, not an automatic guess about complexity. This extraction tests its graph and ordering; it does not rerun multiview generation.

Both frozen profiles use shape1536³, seeds **56/242/42/43**, steps **12/20/12/12**, CFG **7.5/12/7.5/1**, Euler and the retained normal/normal/simple/normal schedulers, structure shift5, texture shift3 and a512MiB decoder chunk budget. Keep CFG override/rescale nodes. Actual checkpoint SHA256 values are in [`checkpoints.json`](../../tools/headkit/checkpoints.json); menu names alone are insufficient.

## Set up a clean checkout

Use the bundled desktop Python, never the Windows Store shim. Install `tools/headkit/requirements.txt` into the declared shared runtime/library bank. Native geometry operations additionally need **libigl2.6.3**, **xatlas0.0.11**, **PyMeshLab2025.7.post1** and, for projected ownership, **Embree4.4.0**. Blender4.0 and the installed NWN:EE compiler are explicitly pinned. None of these binaries or model weights belong in Git.

Copy `tools/headkit/examples/local-bindings.example.json` into ignored local storage. Replace every placeholder with an absolute local binding and SHA256; list consumed library code and native dependencies under each `libraries` entry. Bind the actual executing ComfyUI source files and model roots, including `nodes_trellis2.py`, `flexgemm.py`, the Trellis model and installed adapters. Do not borrow executables from another worktree. Changes to runtimes require fresh shared-tool migration evidence; see [shared tooling](../shared-tooling-and-workflow.md).

Install the self-contained `tools/headkit/comfy_nodes` folder as a fresh `custom_nodes/srn_headkit` using `install-nodes --destination <folder>`. Restart ComfyUI when no other session owns its queue. Installation does not restart it. The request builder verifies installed adapter bytes and the submission guard checks `/object_info`. Existing historical `Srn...` nodes are neither changed nor dependencies of the new graphs.

Put large intermediates and temporary files under **`S:\Scratch\codex-scratch`** on this machine. Keep head manifests, references, meshes, local bindings, requests and receipts under ignored `output/`, `.tools/` or external scratch. Only code, templates, examples and portable research evidence are committed. Before retiring scratch or a worktree, copy the complete used asset chain into durable ignored storage outside it and verify every file hash; a provenance note is not a backup.

## Prepare and review references

Start from `examples/single-image.json` or `examples/multiview.json`. They are templates with deliberately false review flags and placeholder hashes, not approved inputs. Each input is a relative path plus SHA256 inside its manifest folder. Symlink escapes and stale hashes are rejected. Keep immutable intake, generation and processing snapshots rather than editing a manifest while work is running.

1. Make matching **clay geometry** and **detailed appearance** references. Use the same face, pose, perspective, crop and silhouette. Neutral closed mouth; gaze follows the head forward rather than looking sideways at the camera. Keep the full skull, jaw, ears, hair and accessory tips within the frame. Use a near-frontal angle that exposes the important features. A very short closed neck stump is optional; no long neck or shoulders.
2. **Clay hair must be smooth broad coherent masses.** Retain the hairstyle's silhouette, attachment, main parting and large locks. Remove fine strand texture, tiny grooves, ripples, flyaways and corrugation. Do not turn locks into inflated ropes or rigid plates. Hair may flow near the face, but its route, front/back attachment and taper or natural end must be obvious. Show rear hair behind the neck when it belongs there; avoid floating bottom blobs and ambiguous hidden tails.
3. Organic eyes should be rounded, closed smooth surfaces in clay, with no painted brows/lashes or raised brow strands. Keep the anatomical brow ridge and corners. Preserve mechanical cybereye structure; **a cybereye has no eyelashes**. Detailed images retain painted eyes, brows, lashes and original material detail. Skin adjacent to an eye must not become a different-colored patch.
4. Record the counts, anatomical sides, roots, directions and silhouettes of **every horn, tusk, datajack, cybereye and other accessory**. Explicitly record absent features. No duplicate, detached or hidden ambiguous accessory may be accepted as a reference. Hair must not conceal the measurements needed to establish a feature.
5. Measure at least three distinct paired landmarks. `prepare` allows only positive global similarity correction: scale0.97–1.03, rotation≤3°, declared residual, silhouette IoU≥0.94. Review numbered overlays, masks and all silhouette edges. Larger discrepancies require new references, not local warping.
6. For **single image**, feed both aligned images through the **same union mask**,1024-square normalization and padding1.1. `request --stage calibrate` freezes the actual crop/detector graph. Its history nodes10 and16 show detailed/clay horizontal FOV estimates; nodes12/13 save the normalized inputs. Use the detailed estimate as the primary proposal, corroborated by clay. Review25–70° estimates; a discrepancy over8° needs a written decision and inspection, not silent clamping or averaging. FOV estimation from one image is ambiguous; it does not prove camera calibration. Pin normalized outputs as generation inputs `geometry` and `detail`, and use the exact reviewed FOV in both jobs.
7. For **multiview**, prepare front/left/back/right at0/90/180/270° in the workflow's convention. Verify true profiles and a rear image that hides the face (only appropriate ears/horns may peek out). Measure crown, chin and skull center independently in every view: cranial height variation≤2%, center drift≤2% of canvas, same canvas, no clipped silhouette. Do not crop individual views tightly. `prepare_multiview` checks each clay/detail pair and the common frame; depth correspondence and feature inventory still require human review. Stage the already commonly framed geometry images under roles `front`, `left`, `back`, `right`; the detailed front uses role `detail`. Never mix the single-image FOV estimate or checkpoint into this rig.

Set review flags only after these inspections. Preparation does not generate or approve a head.

## Operate the guarded commands

`python -m tools.headkit --help` is read-only help. Processing commands use the maintained shared-tool launcher. With the explicit bundled interpreter, the pattern is:

```text
<BUNDLED_PYTHON> tools/phenotypes/launch_shared_tool.py
  --toolchain <local-toolchain.json>
  --migration-receipt <fresh-migration.json>
  --tool python --output <fresh-launch-directory>
  --input-path-list <JSON-array-of-actual-consumed-input-paths>
  -- tools/headkit/run_headkit.py <command> <arguments>
```

Freeze the manifest, local bindings, toolkit/helper versions, model/library files and actual input assets before dispatch; declare those consumed inputs. The launcher snapshots declared helpers and verifies them afterward. `status`, `inputs` and `--help` need no launcher. Use `inputs --manifest M --bindings B [--run R] --output INPUTS` to build the frozen input-path list from manifests, runtime/model/library bindings, maintained helpers and completed stage receipts; no per-head Python is needed. Include the prepared request itself when submitting and the job intent/submission files when collecting. Commands are stage-oriented so GPU work is never hidden inside `run` or `resume`.

| Command | Operation |
|---|---|
| `prepare --manifest M --bindings B --run R` | Validate and measure reference pairs; save overlays |
| `request --manifest M --bindings B --stage calibrate|geometry|appearance|export --output Q` | Compile one concrete request with checkpoint pins; no dispatch |
| `ledger-init --ledger L --prior-count N --evidence TEXT` | Start from the **reconciled global count**; never reset historical attempts to zero |
| `submit --bindings B --ledger L --request Q --output JOB` | Match request context and rehash frozen inputs under the ledger lock before one POST; require idle shared queue |
| `collect --bindings B --ledger L --token TOKEN --output JOB [--wait]` | Save history and hash actual owned outputs; verify appearance redecodes exactly the saved geometry |
| `reconcile --bindings B --ledger L --token TOKEN` | Recover the original prompt by token, never submit a replacement |
| `run` / `resume --manifest M --bindings B --run R --stage STAGE` | Execute/reuse one declared CPU stage |
| `status --manifest M --bindings B --run R` | Verify receipts and report missing/stale stages |
| `review --manifest M --bindings B --run R --stage STAGE --decision approved|rejected --notes TEXT` | Record an operator decision bound to current receipt hashes |
| `release --bindings B --ledger L` | Hold the submission ledger lock, require reconciled jobs and an idle queue, then unload ComfyUI models |
| `replay --config C --output R` | Read-only roundtrip of retained reviewed artifacts; not regeneration or automatic acceptance |

The local `toolchain`, `migrationReceipt`, `python` and `toolsRoot` bindings must exactly match the verified launcher and running Python; processing refuses mixed runtime identities and records the matched identity in stage receipts.

Each prepared ComfyUI request is bound to that runtime identity, the exact local bindings-file hash and the normalized ComfyUI endpoint. Submission rejects any mismatch and rehashes every frozen request input under the ledger lock immediately before dispatch. If that final check fails, the ledger records `preflight-rejected`; it does not consume a generation attempt.

Model-loader pins also record each Comfy node's model-folder category, selected filename, resolved-path identity and reviewed SHA256. During the locked preflight, the installed `srn_headkit` adapter calls ComfyUI's own loader resolver for those category/name pairs and verifies the resolved file path and bytes. A same-named checkpoint in another model root, changed checkpoint bytes, or a stale adapter rejects the request before `/prompt` and does not consume an attempt. Install the current adapter and restart ComfyUI before preparing model-backed requests; prepare again if its model search paths change.

Declare `comfyRoot`, any external `comfyDependencyRoots` and the complete `comfySources` inventory of Python, configuration and compiled implementation files in those trees. The gate requires the core loader/execution files and Pixal/Trellis/FlexGEMM implementations; a few selected pins are insufficient. Fixed generated-data/model/cache folders are excluded, model weights remain separately pinned, and linked implementation trees are rejected. Inventory membership and bytes are rechecked during request preparation, submission, collection and terminal reuse. This validates configured filesystem sources; restart the instance after implementation changes before preparing new jobs so loaded code agrees with disk.

Use **one shared ledger for both profiles**, one job at a time, maximum100 generation attempts,45-minute deadlines. Model release must use that same ledger: its idle check and `/free` call hold the same lock as submission. Pending or unresolved jobs block release. Only geometry sampling consumes a generation attempt; appearance/export jobs are still tracked and must be reconciled. Failed or uncertain geometry submissions count. An uncertain POST or timed-out job blocks another dispatch. `collect --wait` monitors but does not interrupt a possibly shared running process at timeout. Inspect/cancel only the owned prompt, retain server evidence, then reconcile. Monitoring saves sampled `/system_stats` device occupancy during the collection window; it is not an exact process-memory peak or coverage of the earlier unmonitored interval. Repeated `collect` calls reuse only a verified, ledger-pinned terminal receipt from its original directory. History, memory samples and collection receipts are created once; changed evidence, legacy unpinned terminal jobs and partial files require inspection instead of overwriting. A crashed lock is not automatically stolen. If history cannot uniquely identify a request, keep the intent unresolved and investigate; absence from a bounded history is not proof of non-submission.

After a geometry job, review actual clay from all sides **before** appearance/export work. Unexpected protrusions, duplicate horns/tusks and misplaced masses normally require corrected inputs/regeneration. Preserve raw mesh and sparse checkpoint. Appearance requires pinned `shape` and `geometryRaw` inputs plus an explicit manifest approval:

```json
"approval": {
  "inputReviewComplete": true,
  "generatedGeometry": {
    "decision": "approved",
    "geometryRawSha256": "<SHA256 of the reviewed raw mesh>",
    "shapeSha256": "<SHA256 of its saved shape>",
    "notes": "Reviewed all clay angles, accessory counts and placement, hair routing and underside."
  }
}
```

Comfy export also requires `approval.exportGeometry` with `decision: "approved"`, nonempty `notes` and `exportSourceSha256` matching the pinned `exportSource`. Review that exact mesh after any precluster changes; approval of a different raw mesh does not carry forward. Missing, rejected or stale export approval blocks preparation before staging.

Input-reference approval does not approve the generated mesh. Missing, rejected or stale generated-geometry approval blocks request preparation before any appearance images are staged. It restores native CUDA coordinates, audits latent immutability and rejects a different redecoded mesh. Keep original generated RGB, roughness, metallic and opacity; no AO or unrequested relighting. Release models when the owned GPU work is complete and the shared queue is idle. Do not unload another scheduler's local LLM yourself.

## CPU processing and runtime preparation

Use `examples/processing.json` as the input-role map. Fill annotations per head; examples contain no usable fitting coordinates. The example declares all four `render.mapInputs` roles (`inspectionColor`, `inspectionRoughness`, `inspectionMetallic`, `inspectionOpacity`); replace their placeholder paths/hashes with the selected 2K or 4K maps for this exact UV mesh. Pin the actual selected artifacts; imported `uvMesh`, `runtimeColor`, `runtimeShades` or ownership inputs are explicit checkpoints, not claims that earlier stages ran here. Every imported UV texture (`basecolor4k`, `runtimeColor`, `runtimeShades` and each role named by `render.mapInputs`) requires `approval.textureMaps[role]` with `decision: "approved"`, nonempty `notes`, `textureSha256` matching that input and `sourceSha256` matching the active UV mesh. Keep reference images and stock palettes separate from these UV atlases. Derived UV meshes must have an approved unwrap receipt, and dependent cached stages retain that binding.

1. **Precluster:** `precluster` consumes `raw`, bounds assigned-vertex movement to0.4% of the head diagonal, removes only cluster-created collapsed/duplicate/zero-area faces, compacts and orients components. This bound is **not** a continuous surface-error proof. Keep raw untouched. Bind this oriented source as `exportSource` for the Comfy export job.
2. **UDF export:** use768 remesh, band1,20 smoothing iterations, no projection-back, pole fixing or size-only component deletion. The default request emits the target20K branch only; no unused200K/remesh save branch runs. The appearance checkpoint remains the unchanged source for baking. Preserve the exported copy before cleanup.
3. **Inspect shell before closure:** bind `shellInspection` with exact `sourceSha256`, `visualReviewed`, `confirmedUnintendedOpening` and/or `confirmedShellDefect`. Inspect underside and sections, winding, physical boundaries and visibility. A dark clay region alone is not evidence of a hole. Set `mesh.alphaWrap` only for a confirmed defect. Already sound shells are not capped. No planar disk, added neck or blanket component deletion.
4. **Repair/reduce:** conditional CGAL Alpha Wrap through PyMeshLab uses alpha0.005/offset0.00025 of diagonal. Audit serialized topology, vertex links and complete strict crossings before reduction. Collision-blocking QSlim runs in an owned child with a10-minute limit. Reaudit float32 output, enforce≤20K combined triangles, record ancestry and bidirectional vertex-to-triangle error. Default surface limit0.4%; a measured, specifically reviewed limit can be declared up to2.5%. These vertex samples are not a continuous Hausdorff proof. #73/#74 needed visual quality acceptance beyond the earlier0.4% research gate; do not claim they passed that gate. Failed geometry is retained and not baked by default.
5. **UVs:** `unwrap` preserves ordered triangle-corner positions, winding and authored normals. Use connected fans and bounded local repair, not one chart per triangle. Check actual2K/1K raster coverage, overlap, fragmentation and gutters; source4K maps are also inspected. `reuseReviewedUvs` imports a prior atlas only after audits. Reject mismatches and retain failed receipts. A UV-only pass must not silently change the mesh.
6. **Bake:** `bake` samples the real six-channel saved appearance on final UV surface positions at4K, in65536-sample CPU chunks, four workers. Decoder overshoot needs explicit `allowDecoderOvershoot`; clipping happens **after** interpolation and is counted. Report nearest-field fallback counts. Fill **unmapped padding only**; preserve opaque black pupils/dark hair. Produce2K and1K with BOX filtering, keep actual surface coverage separate from padding. View all atlas images and mapped features; high fallback counts are a review concern, not automatic approval.
7. **Ownership:** supply reviewed discrete0..9 atlas masks or use `ownership` with calibrated view masks, a4×4 view-projection matrix and camera origin per view. Projection uses floating triangle visibility through Embree, not an8-bit vertex depth map. Unknown mapped texels remain failures, never automatic hair. Calibrate and inspect hairline, ears, foreground hair, horn roots, tusks and implants at front and both sides. Separate ownership from RGB; imported atlas and view masks must be eight-bit `L` images. RGB, palette-indexed and higher-bit masks are rejected before reading labels in projection, tone matching, quantization and native export. Channel IDs use nearest selection, never numerical blending. Imported1K/4K masks require `ownership.reviewed: true` and `ownership.sourceSha256` matching the exact active UV mesh, including direct tone, palette and runtime-shade export paths. When `uvMesh` is not imported, their receipts depend on the approved `unwrap` output so later UV changes or review rejection invalidate reuse. If only a reviewed 1K mask is supplied, the tone stage expands it to 4K with nearest-neighbor filtering after validating an eight-bit L image with labels 0..9; the source and expanded-mask hashes are recorded in the receipt. Review the 1K edge limitation. A 1K mask may also be used directly for palette quantization and native export.
8. **Tone:** `tone` matches **original generated skin and hair separately** to reviewed clean reference sample boxes using bounded logit shifts. Retain texture variation and baked shading, protect accessory layers. The source color must be actual 4K; ownership may be a reviewed 4K mask or a recorded nearest-neighbor expansion of a reviewed 1K mask. The tone output is validated at 4K before deriving 2K/1K; smaller imported color maps are rejected. Review generated-reference medians, edges and gradients. The method does not guarantee perfect local complexion matching, and an incorrect semantic mask cannot be fixed by a color shift. Full face/multiview reprojection is outside this default toolkit; a small failed feature should be a bounded reviewed exception, not an inherited sequence of eye/temple repair scripts.
9. **Palette:** `palette` uses explicit stock palette images and rows for each mapped channel. Default skin/hair0/1; valid hardware2/3,cloth4/5,leather6/7,tattoo8/9 may be used intentionally for accessories (e.g. horns/tusks8, cybereye9). Reject transparent palette entries and shade255. Native export also rejects imported shade maps unless they are 1K eight-bit grayscale with every shade below255. Inspect decoded1K texture, each isolated channel and alternate character palette selections. Confirm stock neck skin-shade matching; a bounded recorded `shadeOffsets` correction is allowed. Review skin beneath cyberware and ears/hairline, not just front appearance.
10. **Fit/export/native:** supply measured positive similarity landmarks in NWN basis, or a reviewed matrix bound to the exact source SHA. GLB→NWN basis is`(x,-z,y)`. Use per-head neck contact, forward resting angle and reserved resref; donor coordinates are never defaults. `export` writes one PLT and plain rigid ASCII head. `native` compiles in an isolated user directory, uses the maintained armor fixed-string-tail sanitizer, proves other bytes/decoded corners/normals/UVs unchanged, and produces a verified MDL+PLT-only HAK. No unsupported material textures are packaged. In-game palette, fit and appearance approval remain mandatory and separate.

`render` uses Blender CPU, four threads, matching clay/color-only/material-lit views with actual UV textures and no added AO. The anatomical front angle is a measured manifest input. Default cameras cover front, both profiles, both three-quarter views, back, crown, actual underside, face/ears and cyberware; adjust close-up targets as data when an accessory lies elsewhere. Render2K inspection sheets/atlases and actual1K viewing-distance previews. The processing example sets `render.sizes` to `[2048, 1024]`, also the default. Each size renders all selected cameras and all three materials with the same framing and lighting. The 1K pass uses actual BOX-filtered 1K textures, not resized 2K screenshots. Outputs live under `renders/2048/` and `renders/1024/`, with per-material view folders, native-resolution labeled `*-sheet.png` contact sheets, and full-resolution base-color/roughness/metallic/opacity images under `atlases/`. Atlas sources must be at least the requested resolution; the renderer rejects upsampling. A single explicit `render.size` remains available for diagnostic smoke tests and does **not** satisfy delivery review. A render receipt records timings, dimensions, atlas and sheet hashes but never a visual pass.

## Resume, limits and delivery

Each CPU attempt has an intent, immutable receipt, input/output hashes, code version, elapsed time and preserved diagnostics. Every CPU stage requires an explicit `review --stage STAGE --decision approved --notes TEXT` before its output can feed downstream processing. Inspect the stage's emitted evidence/files first; numerical completion is not approval. The current decision is stored in runner state as a hash-pinned immutable review bound to that exact stage receipt. Missing/rejected/stale approval blocks consumers, including cached downstream outputs and native packaging. A rejected stage can be inspected and reviewed again without recomputing it; old decisions remain preserved. `status` reports numerical completion separately from pending/approved/rejected review. Imported pinned checkpoints remain an explicit operator-selected entry point, not an approval of earlier stages.

A completed stage is reused only while manifest, bindings, code, dependencies and outputs still match. This initial implementation conservatively invalidates the whole run snapshot when manifest/code changes; create a new phase snapshot or explicitly import pinned reviewed checkpoints. No per-head Python is required. After two failures on the same manifest/code, stop and prepare an exception with exact scope; do not relax gates or keep looping. A transient GPU dispatch failure is reconciled, not retried blindly.

Initial extraction supports static single-primitive identity-node GLBs in the normalized Pixal coordinate frame. Unsupported transforms, skins, extensions and multiple primitives are rejected explicitly. New races/styles and unreviewed geometry are trials; replaying two accepted Troll assets establishes transport/packaging evidence, not an autonomous factory across arbitrary heads. See [validation evidence](headkit-validation.md).

For `replay`, every consumed `source`, `shades`, `layers`, `binary` and `expectedPlt` path must have a matching input SHA256 pin. Replay resolves aliases before processing, rejects missing/conflicting pins, uses those resolved paths and verifies the frozen pins again before writing successful replay evidence. The receipt records the exact consumed role bindings.

Deliver pinned raw/exported/final meshes, generated appearance, final atlases and actual1K PLT, clay/textured views, isolation overlays, numeric defects, review decisions, native proof and a resume checkpoint. Keep all historical failures. User approval of in-game inspection is required before promoting a new candidate; generation success, numerical checks and rendering do not confer that approval.

Render plans require nonempty camera and material-mode lists. Every requested size/mode/camera combination must produce exactly one frame before the render stage can succeed; empty or incomplete plans cannot be approved as inspection evidence.
