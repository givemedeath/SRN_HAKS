# Head generation toolkit: operator runbook v1

This is the fresh entry point for new heads. Historical runbooks remain research evidence; their donor coordinates and repair experiments are not defaults. The toolkit extracts the successful #73/#74 single-image route and retains attempt51 as the alternate multiview baseline. It produces review candidates, not automatic production approval.

## Choose the input route

| Route | Use | Geometry conditioning | Appearance conditioning | Camera |
|---|---|---|---|---|
| `pixal-single-v1` (default) | A design whose full hairstyle and accessories are unambiguous in one near-frontal angled image | One smooth clay image, native `Pixal3DConditioning`, single-image checkpoint | Matching detailed image on the exact saved shape | Reviewed horizontal MoGe estimate, shared between geometry and appearance |
| `pixal-multiview-v1` (alternate) | Complex rear hair, horns, tusks or cyberware that one image cannot establish | Four measured cardinal **smooth-clay** images through `Pixal3DMultiViewConditioning`, **multiview checkpoint** | The four matching **detailed** cardinal images, through the same multiview conditioner/checkpoint, on the saved shape | Retained **20°** rig, 90° view spacing, common framing |

The alternate's graph, checkpoint and rig come from corrected-input attempt51, which later reached an accepted in-game result after downstream repair. Multiview conditioning follows the same split as single image: mesh generation uses **smooth-clay** views only and texture generation uses the matching **detailed** views only. Attempt51 instead used blank-orbit geometry references and a front-only detailed texture input; that historical control remains evidence and is not the current route. Smooth-clay/four-detail multiview has had only one unguarded diagnostic GPU run (see [validation](headkit-validation.md#unguarded-multiview-trial-2026-10-22)), so new heads through it remain trials. Attempt52 had duplicated accessories and is not the baseline. The later front/back experiments are not substituted for this four-view baseline. Multiview is an explicit operator choice, not an automatic guess about complexity. This extraction tests its graph and ordering; it does not rerun multiview generation.

Both frozen profiles use shape1536³, seeds **56/242/42/43**, steps **12/20/12/12**, CFG **7.5/12/7.5/1**, Euler and the retained normal/normal/simple/normal schedulers, structure shift5, texture shift3 and a512MiB decoder chunk budget. Keep CFG override/rescale nodes. Actual checkpoint SHA256 values are in [`checkpoints.json`](../../tools/headkit/checkpoints.json); menu names alone are insufficient.

## Set up a clean checkout

Use the bundled desktop Python, never the Windows Store shim. Install `tools/headkit/requirements.txt` into the declared shared runtime/library bank. Bind the actual `site-packages` directory used by NumPy, Pillow and SciPy as `pythonPackages` in local bindings, with an exact recursive SHA256 inventory of every regular file (including `.pyc`, distribution metadata and companion native-library folders). Keep it under `toolsRoot`, reject links, and refresh the inventory after any package installation or update. Each CPU-stage receipt records the complete package pins and verifies the unchanged inventory before and after processing. Native geometry operations additionally need **libigl2.6.3**, **xatlas0.0.11**, **PyMeshLab2025.7.post1** and, for projected ownership, **Embree4.4.0**. Blender4.0 and the installed NWN:EE compiler are explicitly pinned. None of these binaries or model weights belong in Git.

Copy `tools/headkit/examples/local-bindings.example.json` into ignored local storage. Replace every placeholder with an absolute local binding and SHA256. Each `libraries` entry names a dedicated installation root and must pin **every file recursively under it**, including Python modules and native extensions; links are rejected. Bind the actual executing ComfyUI source files and model roots, including `nodes_trellis2.py`, `flexgemm.py`, the Trellis model and installed adapters. Do not borrow executables from another worktree. Changes to runtimes require fresh shared-tool migration evidence; see [shared tooling](../shared-tooling-and-workflow.md).

Install the self-contained `tools/headkit/comfy_nodes` folder as a fresh `custom_nodes/srn_headkit` using `install-nodes --bindings <local-bindings.json> --destination <folder>`, only in an idle dedicated deployment. Installation writes a local `source-roots.json` snapshot beside the adapter and does not restart ComfyUI. Refresh local `comfySources` pins to include the installed adapter, then follow [Controlled Comfy startup](#controlled-comfy-startup) below. Existing historical `Srn...` nodes are neither changed nor dependencies of the new graphs.

The bootstrap verifies frozen source/runtime files and declared configuration before importing ComfyUI. When the adapter loads, it captures runtime identity (including Python/Torch metadata) and binds it to the controlled session and configuration. The request builder verifies the installed adapter and snapshot bytes; dispatch checks `/object_info` and requires the same bound runtime/session under the shared-ledger lock. On `/headkit/runtime-identity` queries, the adapter rechecks current on-disk inventories, declared arguments/environment and session identity, then returns the startup runtime identity. Comfy source roots are separately pinned by `comfySourceInventory` and excluded from the general runtime inventory.

This contract assumes trusted reviewed plugins and an unchanged installation throughout the session. It does not inspect loaded objects, compare live Python state to source, or detect in-memory mutations or imports made from temporarily changed-and-restored files between checks. Hot reload and attaching an arbitrary running server are unsupported. After any software/configuration change, start a fresh controlled session and prepare new requests; do not use a restored file hash as proof of the prior process's loaded state.

Put large intermediates and temporary files under **`S:\Scratch\codex-scratch`** on this machine. Keep head manifests, references, meshes, local bindings, requests and receipts under ignored `output/`, `.tools/` or external scratch. Only code, templates, examples and portable research evidence are committed. Before retiring scratch or a worktree, copy the complete used asset chain into durable ignored storage outside it and verify every file hash; a provenance note is not a backup.

## Generate design proposals (direct dispatch)

`design` and `design-inpaint` make Flux.2 head design images for a human to choose from. **They use a direct-dispatch path**: one unguarded `POST /prompt` to the bound local ComfyUI, then `/history` polling. They have none of the guarded `submit`/`collect` contract (no ledger or generation count, no idle-queue check, no server runtime identity, no verified model loaders); that route needs the managed `srn_headkit` adapter, which is still undeployed. **Every output is a design proposal for human review.** These commands approve nothing and pin nothing as a manifest reference; a chosen design still goes through [Prepare and review references](#prepare-and-review-references).

Both commands run under the shared-tool launcher like the processing commands. They read `comfyUrl` (local HTTP only), `comfyInput` and `comfyOutput` from `--bindings`. The graphs are [`templates/flux2-design.json`](../../tools/headkit/templates/flux2-design.json) and [`templates/flux2-inpaint.json`](../../tools/headkit/templates/flux2-inpaint.json): Flux.2 dev fp8mixed with the Flux.2 turbo LoRA (strength 1), the Mistral Flux.2 text encoder, Euler, **8 steps, 1024 square, guidance 4.0**, and one `ReferenceLatent` per reference image. The design spec is JSON with `common` text, named `designs` (safe IDs) and optionally `neckInpaint` with a `SKIN` placeholder (`neckEdit` is accepted and ignored); other keys are rejected.

| Command | Operation |
|---|---|
| `design --bindings B --spec S --head H --seed N [--batch K] [--reference IMG ...] --output DIR` | Prompt = `designs[H]` + newline + `common`. K (1–8, default 1) candidates from one seed, conditioned on up to four reference images (normally one species reference). Writes `DIR/H-sN-b0..K-1.png` and the receipt `DIR/H-sN.json` |
| `design-inpaint --bindings B --spec S --design PNG --skin TEXT --seed N [--batch K] [--cut ROW \| --lift PX] [--name NAME] --output DIR` | Resamples only the rows from the cut row downward (normally the neck) of a chosen design. The design is matted with the toolkit matte. The default cut is the neck waist (narrowest silhouette row 62–97% down the subject) minus `--lift` (default 24). A cut row in the top half of the matte, or below the subject, is rejected. The mask (255 from the cut row down, Gaussian blur 6) drives `SetLatentNoiseMask` on the design's own latent, repeated per batch item (default 2), with the design as `ReferenceLatent`. Prompt = `neckInpaint` with `SKIN` replaced. Writes `NAME-inpaint-sN-mask.png`, `-b*.png` and `.json` (NAME defaults to the design file stem). **Carve mode** (`--carve-top ROW --keep x,y x,y ... --stump cx,wTop,wBottom,ySide,yBottom`, no `--cut`) is for a design whose wide bust leaves ghost fringes or flared wings under a row cut: the staged image is a guide that keeps the design above the top row and inside the jaw keep polygon, keeps the design's own neck skin only inside the stump outline (straight sides to `ySide`, rounded closed bottom to `yBottom`) and fills the rest with the corner backdrop; the mask resamples everything outside the keep region. The guide is written as `NAME-inpaint-sN-guide.png` and pinned in the receipt with the carve parameters |

Inputs are staged by copy into `comfyInput/headkit-design/<token>/`, and SaveImage writes under `comfyOutput/headkit-design/<token>/`. Only outputs inside that token prefix are collected. Each receipt is written once and records `state` (`complete`, or `failed` with the error and any prompt ID). It pins (path + SHA256) the spec, the bindings, every source and staged input image (including the inpaint design and mask), and every Comfy output and its copy. It also records the prompt text, seed, batch, fixed settings, the full graph and `graphSha256`, the endpoint, the launcher runtime identity, the toolkit `codeVersion` and `elapsedSeconds` (dispatch to history completion). Inpaint receipts add the matte rows, waist row, cut row and its source, and the mask rule. Receipts carry `proposalOnly: true` and `reviewRequired: true`. An existing receipt for the same name and seed blocks a rerun; choose another seed or output folder. A job is never resubmitted. After the 45-minute polling deadline, inspect the queue by hand.

## Prepare and review references

Start from `examples/single-image.json` or `examples/multiview.json`. They are templates with deliberately false review flags and placeholder hashes, not approved inputs. Each input is a relative path plus SHA256 inside its manifest folder. Symlink escapes and stale hashes are rejected. Keep immutable intake, generation and processing snapshots rather than editing a manifest while work is running.

1. Make matching **clay geometry** and **detailed appearance** references. Use the same face, pose, perspective, crop and silhouette. Neutral closed mouth; gaze follows the head forward rather than looking sideways at the camera. Keep the full skull, jaw, ears, hair and accessory tips within the frame. Use a near-frontal angle that exposes the important features. A very short closed neck stump is optional; no long neck or shoulders.
2. **Clay hair must be smooth broad coherent masses.** Retain the hairstyle's silhouette, attachment, main parting and large locks. Remove fine strand texture, tiny grooves, ripples, flyaways and corrugation. Do not turn locks into inflated ropes or rigid plates. Hair may flow near the face, but its route, front/back attachment and taper or natural end must be obvious. Show rear hair behind the neck when it belongs there; avoid floating bottom blobs and ambiguous hidden tails.
3. Organic eyes should be rounded, closed smooth surfaces in clay, with no painted brows/lashes or raised brow strands. Keep the anatomical brow ridge and corners. Preserve mechanical cybereye structure; **a cybereye has no eyelashes**. Detailed images retain painted eyes, brows, lashes and original material detail. Skin adjacent to an eye must not become a different-colored patch.
4. Record the counts, anatomical sides, roots, directions and silhouettes of **every horn, tusk, datajack, cybereye and other accessory**. Explicitly record absent features. No duplicate, detached or hidden ambiguous accessory may be accepted as a reference. Hair must not conceal the measurements needed to establish a feature.
5. Measure at least three distinct paired landmarks. `prepare` allows only positive global similarity correction: scale0.97–1.03, rotation≤3°, declared residual, silhouette IoU≥0.94. Review numbered overlays, masks and all silhouette edges. Larger discrepancies require new references, not local warping.
6. For **single image**, feed both aligned images through the **same union mask**,1024-square normalization and padding1.1. `request --stage calibrate` freezes the actual crop/detector graph. Its history nodes10 and16 show detailed/clay horizontal FOV estimates; nodes12/13 save the normalized inputs. Use the detailed estimate as the primary proposal, corroborated by clay. Review25–70° estimates; a discrepancy over8° needs a written decision and inspection, not silent clamping or averaging. FOV estimation from one image is ambiguous; it does not prove camera calibration. Pin normalized outputs as generation inputs `geometry` and `detail`, and use the exact reviewed FOV in both jobs.
7. For **multiview**, prepare front/left/back/right at0/90/180/270° in the workflow's convention. Verify true profiles and a rear image that hides the face (only appropriate ears/horns may peek out). Measure crown, chin and skull center independently in every view: cranial height variation≤2%, center drift≤2% of canvas, same canvas, no clipped silhouette. Do not crop individual views tightly. `prepare_multiview` checks each clay/detail pair and the common frame; depth correspondence and feature inventory still require human review. Pin each view's aligned smooth clay (`geometry-pair.png`) as generation role `geometryFront`, `geometryLeft`, `geometryBack` or `geometryRight`, and its aligned detailed image (`detail-pair.png`) as `detailFront`, `detailLeft`, `detailBack` or `detailRight`. Geometry requests stage only the four clay roles; appearance requests stage only the four detailed roles. Clay must follow step 2 (smooth broad hair masses, closed eyes) in every view, including the rear. Never mix the single-image FOV estimate or checkpoint into this rig.

A **design** manifest (one bootstrap image, input role `design`) is matted in `prepare` from its plain studio backdrop: background is the near-backdrop, low-saturation region connected to the canvas border (`matte.backgroundTolerance`, 4–40, default 14), so interior gray features stay opaque. Lower the tolerance when pale skin sits close to the backdrop and the matte eats into the neck. Backdrop the subject fully encloses, such as the gap inside a curled horn, stays opaque by default. Opt-in `matte.enclosedBackgroundMinimumPixels` (50–100000) clears every enclosed near-backdrop region at least that large; `matte.json` records each cleared region's size, centre and box. Review `matte-check.png` for gray features it may have taken.

Set review flags only after these inspections. Preparation does not generate or approve a head.

## Operate the guarded commands

`python -m tools.headkit --help` is read-only help. Processing commands use the maintained shared-tool launcher. With the explicit bundled interpreter, the pattern is:

```text
<BUNDLED_PYTHON> tools/phenotypes/launch_shared_tool.py
  --toolchain <local-toolchain.json>
  --migration-receipt <fresh-migration.json>
  --tool python --output <fresh-launch-directory>
  --input-path-list <JSON-array-of-actual-consumed-input-paths>
  -- tools/headkit/run_headkit.py <command> <arguments>
```

Freeze the manifest, local bindings, toolkit/helper versions, model/library files and actual input assets before dispatch; declare those consumed inputs. The launcher snapshots declared helpers and verifies them afterward. Nested Blender launches carry the full toolkit/helper inventory and render configuration through a hash-bound input manifest, so their receipts retain imported helper snapshots; Blender verifies those same helper hashes before and after rendering. The native compiler and sanitizer import dependencies and their consumed configuration are included in the toolkit inventory as well. `status`, `inputs` and `--help` need no launcher. Use `inputs --manifest M --bindings B [--run R] [--stages a,b] --output INPUTS` to build the frozen input-path list (with `--stages`, only those stages' declared manifest inputs and libraries plus the receipts, outputs and reviews of their upstream chain; stage receipts likewise pin only the declared inputs and libraries a stage actually read, and an undeclared read fails the stage) from manifests, runtime/model/library bindings, maintained helpers, the installed adapter Python files and `source-roots.json`, and completed stage receipts. A configured Comfy adapter must have its installed source snapshot; missing snapshots stop input enumeration; no per-head Python is needed. Include the prepared request itself when submitting and the job intent/submission files when collecting. Commands are stage-oriented so GPU work is never hidden inside `run` or `resume`.

| Command | Operation |
|---|---|
| `startup-config --bindings B --output C` | Freeze an offline controlled-startup manifest; never start/contact ComfyUI |
| `prepare --manifest M --bindings B --run R` | Validate and measure reference pairs; save overlays |
| `request --manifest M --bindings B --stage calibrate|geometry|appearance|export --output Q` | Compile one concrete request with checkpoint pins; no dispatch |
| `ledger-init --ledger L --prior-count N --evidence TEXT` | Start from the **reconciled global count**; never reset historical attempts to zero |
| `submit --bindings B --ledger L --request Q --output JOB` | Match request context and rehash frozen inputs under the ledger lock before one POST; require idle shared queue |
| `collect --bindings B --ledger L --token TOKEN --output JOB [--wait]` | Save history and hash actual owned outputs; verify appearance redecodes exactly the saved geometry |
| `reconcile --bindings B --ledger L --token TOKEN` | Recover the original prompt by token, never submit a replacement |
| `run` / `resume --manifest M --bindings B --run R --stage STAGE` | Execute/reuse one declared CPU stage |
| `chain --manifest M --bindings B --run R --stages a,b,c [--approve S --notes N]` | Execute/reuse the listed CPU stages in pipeline order under the same launcher and run lock; print per-stage `reused`/`ran` (receipt `elapsedSeconds`)/`blocked-on-review`/`failed` JSON. Stops cleanly at the first stage whose dependency lacks an approved review, naming the attempt folder to inspect; never records a review of a stage it runs. `--approve S --notes N` first records the operator's approval of the already-inspected gating stage `S` (as `review` would), so a review and the next stages share one launch; build that launch's inputs with `inputs --stages S,a,b,c`. A failure exits 1 with its attempt folder, and rerunning the same chain resumes at that stage |
| `status --manifest M --bindings B --run R` | Verify receipts and report missing/stale stages |
| `review --manifest M --bindings B --run R --stage STAGE --decision approved|rejected --notes TEXT` | Record an operator decision bound to current receipt hashes |
| `release --bindings B --ledger L` | Hold the submission ledger lock, require reconciled jobs and an idle queue, then unload ComfyUI models |
| `replay --config C --output R` | Read-only roundtrip of retained reviewed artifacts; not regeneration or automatic acceptance |

The local `toolchain`, `migrationReceipt`, `python` and `toolsRoot` bindings must exactly match the verified launcher and running Python; processing refuses mixed runtime identities and records the matched identity in stage receipts. Install the headkit adapters in an idle dedicated deployment and use controlled startup before preparing a request: model loader nodes carry the reviewed checkpoint hash and resolved path identity in their cache signature, then recheck the bytes immediately before loading. The Embree DLL must resolve inside the declared durable shared tools root.

Each prepared ComfyUI request is bound to the shared-tool launcher identity, the live ComfyUI server runtime fingerprint, the exact local bindings-file hash and the normalized ComfyUI endpoint. Submission rejects any mismatch and rehashes every frozen request input under the ledger lock immediately before dispatch. If that final check fails, the ledger records `preflight-rejected`; it does not consume a generation attempt.

Model-loader pins also record each Comfy node's model-folder category, selected filename, resolved-path identity and reviewed SHA256. During the locked preflight, the installed `srn_headkit` adapter calls ComfyUI's own loader resolver for those category/name pairs and verifies the resolved file path and bytes. A same-named checkpoint in another model root, changed checkpoint bytes, or a stale adapter rejects the request before `/prompt` and does not consume an attempt. Install the current adapter and restart ComfyUI before preparing model-backed requests; prepare again if its model search paths change.

Declare `comfyRoot`, external `comfyDependencyRoots` and the complete `comfySources` inventory. Every regular file in the implementation trees is inventoried regardless of extension, including text prompts, INI/config files, extensionless resources, native code and sourceless `.pyc` modules. Membership and hashes remain mandatory at preparation, dispatch and collection. Only version-control metadata, `__pycache__`, the adapter snapshot itself (pinned separately), and the core-level `input`, `output`, `temp`, `models`, `user`, `.venv` and `venv` directories are excluded. Keep generated data, logs, caches, model weights and job inputs in their separate bound locations; files consumed there still need the appropriate runtime/model/request pins. A plugin writing into its implementation tree invalidates the session. Existing filtered snapshots must be regenerated before preparing new requests. The supported trust boundary is a reviewed local installation and trusted plugins. Hot reload, runtime monkeypatching and attaching an arbitrary already-running server are unsupported; this is reproducible deployment provenance, not a Python sandbox. The retired object/AST census and its research tests remain in Git at `7d2259fef471406343e0dba0db66fb82f7f71f6c` and in verified historical evidence. They no longer define the active runtime contract.

### Controlled Comfy startup

1. Use a dedicated, idle Comfy deployment with separate input, output, temp and user directories. Do not install into, restart, unload or terminate another running instance. If the intended deployment or port is occupied, stop and wait for its owner. Keep the scheduler-approved endpoint (normally port 8188); do not start a second GPU server on another port to bypass shared GPU coordination. Installation and first live startup are separate operator steps; this PR's tests use temporary CPU fixtures only.
2. Install the reviewed adapters into that deployment, then refresh its exact source inventory. Declare `comfyPython` (path/hash), `comfyRuntimeRoots` (complete interpreter/library installations, separate from source/model trees), and `comfyStartup` with `endpoint`, `arguments` and a clean explicit `environment`. The endpoint must be an explicit `http://127.0.0.1:PORT`; arguments cannot override its listen address/port. Use full option names for input/output directories; abbreviations of these options or the protected endpoint options are rejected. Exactly one input-directory and output-directory option must match `comfyInput` and `comfyOutput`. Require exactly one explicit absolute `--user-directory`; declare that dedicated directory as an additional `comfyDependencyRoots` entry outside the Comfy core tree, with all its regular files included in `comfySources`. Default/uninventoried user directories, abbreviated user options and the `--` option terminator are rejected. Its configuration is immutable during a session; direct logs, caches and generated state to separately bound scratch/output locations. A plugin that writes into this settings directory invalidates the session and must be configured before a fresh snapshot; do not add ignore patterns to bypass that failure. Put TEMP/TMP and compiler caches under the scratch binding. Include the OS paths needed by that interpreter; keep credentials out of the configuration. Python environment overrides are unsupported under isolated startup.
3. Through the shared-tool launcher, run `startup-config --bindings B --output STARTUP.json`. It only writes a frozen deployment manifest outside all inventoried roots. It verifies interpreter, runtime membership, source membership and installed adapter bytes; it never starts or contacts ComfyUI. Bind the resulting file as `comfyStartupConfig`, then regenerate the launch input list.
4. When the deployment and GPU are available, explicitly start `<COMFY_PYTHON> -I -B <COMFY_CUSTOM_NODES>/srn_headkit/managed_startup.py --config STARTUP.json --receipt FRESH.json`. This server bootstrap has its own preflight and exit receipt. It verifies deployment files before importing Comfy, applies the declared environment, assigns a fresh process/session identity and uses a fresh bytecode-cache location. A busy port fails without contacting or stopping its owner. No managed startup is performed automatically by request/run/resume.
5. Request preparation binds the exact startup configuration, settings digest, session ID/PID, source/runtime files, workflow, model weights and reviewed references. Dispatch requires the same session under the existing shared ledger lock. A restart, changed configuration or changed files requires new preparation; software/configuration updates require a new controlled session. One unchanged session may serve a batch, with existing shared-queue GPU coordination and model release retained.
6. The adapter rechecks the frozen deployment and declared settings on runtime queries. Completed processing verifies the frozen inputs again, and the bootstrap verifies its deployment on exit. Source-state introspection has been removed. Geometry approval, review decisions, mesh/UV/texture/PLT/native checks remain independent and mandatory. Historical schema-2 requests are preserved as evidence and require fresh preparation for this schema-3 contract.

Use **one shared ledger for both profiles**, one job at a time, maximum100 generation attempts,45-minute deadlines. Model release must use that same ledger: its idle check and `/free` call hold the same lock as submission. Pending or unresolved jobs block release. Only geometry sampling consumes a generation attempt; appearance/export jobs are still tracked and must be reconciled. Failed or uncertain geometry submissions count. An uncertain POST or timed-out job blocks another dispatch. `collect --wait` monitors but does not interrupt a possibly shared running process at timeout. Inspect/cancel only the owned prompt, retain server evidence, then reconcile. Monitoring saves sampled `/system_stats` device occupancy during the collection window; it is not an exact process-memory peak or coverage of the earlier unmonitored interval. Repeated `collect` calls reuse only a verified, ledger-pinned terminal receipt from its original directory. History, memory samples and collection receipts are created once; changed evidence, legacy unpinned terminal jobs and partial files require inspection instead of overwriting. A crashed lock is not automatically stolen. If history cannot uniquely identify a request, keep the intent unresolved and investigate; absence from a bounded history is not proof of non-submission.

After a geometry job, review actual clay from all sides **before** appearance/export work. Unexpected protrusions, duplicate horns/tusks and misplaced masses normally require corrected inputs/regeneration. Preserve raw mesh and sparse checkpoint. Appearance requires pinned `shape` and `geometryRaw` inputs plus an explicit manifest approval:

```json
"approval": {
  "inputReviewComplete": true,
  "generatedGeometry": {
    "decision": "approved",
    "geometryRawSha256": "<SHA256 of the reviewed raw mesh>",
    "shapeSha256": "<SHA256 of its saved shape>",
    "notes": "Reviewed all clay angles, accessory counts and placement, hair routing and underside."
  }
}
```

Comfy export also requires `approval.exportGeometry` with `decision: "approved"`, nonempty `notes` and `exportSourceSha256` matching the pinned `exportSource`. Review that exact mesh after any precluster changes; approval of a different raw mesh does not carry forward. Missing, rejected or stale export approval blocks preparation before staging.

Input-reference approval does not approve the generated mesh. Missing, rejected or stale generated-geometry approval blocks request preparation before any appearance images are staged. It restores native CUDA coordinates, audits latent immutability and rejects a different redecoded mesh. Keep original generated RGB, roughness, metallic and opacity; no AO or unrequested relighting. Release models when the owned GPU work is complete and the shared queue is idle. Do not unload another scheduler's local LLM yourself.

## CPU processing and runtime preparation

Use `examples/processing.json` as the input-role map. Fill annotations per head; examples contain no usable fitting coordinates. The example declares all four `render.mapInputs` roles (`inspectionColor`, `inspectionRoughness`, `inspectionMetallic`, `inspectionOpacity`); replace their placeholder paths/hashes with the selected 2K or 4K maps for this exact UV mesh. Pin the actual selected artifacts; imported `uvMesh`, `runtimeColor`, `runtimeShades` or ownership inputs are explicit checkpoints, not claims that earlier stages ran here. Every imported UV texture (`basecolor4k`, `metallic4k`, `runtimeColor`, `runtimeShades` and each role named by `render.mapInputs`) requires `approval.textureMaps[role]` with `decision: "approved"`, nonempty `notes`, `textureSha256` matching that input and `sourceSha256` matching the active UV mesh. Keep reference images and stock palettes separate from these UV atlases. Derived UV meshes must have an approved unwrap receipt, and dependent cached stages retain that binding.

1. **Precluster:** `precluster` consumes `raw`, bounds assigned-vertex movement to0.4% of the head diagonal, removes only cluster-created collapsed/duplicate/zero-area faces, compacts and orients components. This bound is **not** a continuous surface-error proof. Keep raw untouched. Bind this oriented source as `exportSource` for the Comfy export job.
   **Fit (bootstrap):** with `fit.matrixFrom: "fit"` (and no manifest `matrix`/`reviewed`), the `fit` stage proposes the matrix from this run's reviewed precluster output (or `comfyExport`) against the `fitReference` ASCII head (`fit-propose` logic, `fit.excludeLower`, default 0.25) and writes an overlay. Its stage review is the fit review; repair (neck shaping) and export then use that reviewed matrix, so no manifest edit follows precluster. `fit.align: "nose"` keeps the profile-matched scale but places the head by nose tips. The source tip is searched only within 1.5 cm of the height where the profile fit puts the reference nose, so tusks or a lip further forward than the nose cannot win, and a nose placement more than 2 cm from the profile placement is refused for review (`noseProfileShift` is recorded). `align: "profile"` uses the profile placement alone.
2. **UDF export:** use768 remesh, band1,20 smoothing iterations, no projection-back, pole fixing or size-only component deletion. The default request emits the target20K branch only; no unused200K/remesh save branch runs. The appearance checkpoint remains the unchanged source for baking. Preserve the exported copy before cleanup.
3. **Inspect shell before closure:** bind `shellInspection` with exact `sourceSha256`, or, when the manifest has `raw` and no `comfyExport`, chain `repair` on this run's reviewed `precluster` output and declare `mesh.shellInspection` inline (no `sourceSha256`; it is bound to that output at execution), `visualReviewed`, `confirmedUnintendedOpening` and/or `confirmedShellDefect`. Inspect underside and sections, winding, physical boundaries and visibility. A dark clay region alone is not evidence of a hole. Set `mesh.alphaWrap` only for a confirmed defect. Already sound shells are not capped. No planar disk, added neck or blanket component deletion; the only cap is the explicit reviewed neck seal in step 4.
4. **Repair/reduce:** conditional CGAL Alpha Wrap through PyMeshLab uses alpha0.005/offset0.00025 of diagonal. Audit serialized topology, vertex links and complete strict crossings before reduction. Collision-blocking QSlim runs in an owned child with a10-minute limit. Reaudit float32 output, enforce≤20K combined triangles, record ancestry and bidirectional vertex-to-triangle error. Default surface limit0.4%; a measured, specifically reviewed limit can be declared up to2.5%. These vertex samples are not a continuous Hausdorff proof. #73/#74 needed visual quality acceptance beyond the earlier0.4% research gate; do not claim they passed that gate. Failed geometry is retained and not baked by default.
   **Optional neck shaping** (`mesh.neck`) runs here, before UVs, so late shape edits never invalidate texture work. It needs the reviewed fit matrix (`fit.matrix`, `fit.reviewed: true`); the head-local frame is that matrix applied after GLB→NWN `(x,-z,y)` (face +y, up +z). `taper` `{minScale, frontStart, backStart, axis}` scales the **dense master before QSlim** radially about the head-local `axis` `[x, y]`: scale 1 above a start height that follows the jaw (`frontStart` under the chin, `backStart` behind it, blended by `((1+cos φ)/2)²` around the axis), then a smoothstep to `minScale` at the rim. Its slope is zero at both ends, so it forms no shelf or lip; facing walls of the thin wrapped stump share each ray's scale and keep their order. Tapering a reduced shell crosses itself; tapering the master does not. `shorten` `{start, rim}` (optional `band`, default 0.02, 0.005–0.05) shortens an over-long stump first: below the head-local `start` height every depth `d` becomes `s·d + (1−s)·band·(1−e^(−d/band))`, slope 1 at the start (no crease) easing to a solved far scale `s` so the rim reaches `rim`. The map is strictly increasing in each vertical column, so the surface cannot fold, x and y never move and the rounded end keeps its shape; a target the band cannot reach (scale below 0.1) is refused. Taper starts are head-local heights after shortening. The record holds the previous and new rim, far scale and removed length. The untapered master is kept as `master-untapered.glb`, and surface error is measured against the tapered master. `seal` `{height, inset, rise}` (optional `margin` 0.003, `step` 0.0005, `segments` 24, `searchTop`) adds after QSlim a closed flat cone cap (`2×segments` triangles, reserved from the 20K budget before reduction) on the star-shaped inner outline of the neck section: per direction, the nearest section point × `inset`. `height: "measured"` scans down from the higher taper start (or `searchTop`) for the lowest closed horizontal ring (density-independent angular coverage) and adds `margin`. The final shell, cap included, is reaudited for topology and crossings. The result records every parameter, the measured height, cap triangle count, moved vertices and timings. **Neck removal (`cut`, the default for troll heads from 2026-10-25):** a head ends under the jaw and the body's own neck part forms the neck, as on stock heads, so nothing long hangs below the head joint to show through the body in animation. `cut` `{height, slope, band, offset, reach, rise, clearance}` needs the `bodyNeck` input, the body's neck part in the head frame, written by `python -m headkit.body_neck --skeleton pfg0.mdl --neck pfg0_neck001.mdl --output body-neck.json` from decompiled ASCII (`inv(head_g) @ neck_g`). The plane is `z = height + slope*y` (slope −0.2 puts the throat lower than the nape). `height: "measured"` places it `clearance` (default 1 cm) under the lowest front feature that stands more than `reach` outside the body neck (chin, jaw corners, tusks, beard), searched only above `searchBottom` (default −0.16 m head-local): a long generated neck flares into a bust base from about −0.19 that also stands outside the body neck. With the bound, the measured plane reproduced the reviewed explicit heights of troll batch v2 (chins down to −0.136); without it the search landed on the bust at −0.22 to −0.25. Over `band` (default 3 cm) above the plane the stub is drawn radially onto the body neck surface plus `offset` (default −3 mm, just inside it); the weight is a height smoothstep times a reach smoothstep that fades out toward the plane, so features above the plane do not move, the cut lands on the surface and there is no shelf. Use a larger `reach` (8 cm) for necks that stand 5–7 cm off the body neck. A single cut ring gets a shallow fan cap (`rise`, default 3 mm); several rings (an Alpha-Wrapped open stump is double-walled) are closed by re-running the repair's Alpha Wrap, which seals them inside the body neck; an unwrapped repair refuses them. `cut` replaces `seal` and the stump shortening/taper. `shorten` with a rim below the current one lengthens instead. Repair and neck shaping live in `neck.py`, apart from `mesh.py`, so tuning them stales only repair and its dependants, not precluster, export or native. Troll-male-01 reference: `minScale` 0.5, starts −0.078/−0.035, axis `[0, 0.03]`, measured seal −0.058, `inset` 0.9, `rise` 0.003. Review matched front, side, rear and underside views; a numerical pass does not approve the shape.
5. **UVs:** `unwrap` preserves ordered triangle-corner positions, winding and authored normals. Use connected fans, not one chart per triangle. xatlas charts the mesh once (`mesh.uv.chartOptions`); every repair round is pack-only: faces that overlap, degenerate or fail the sub-texel rule become planar single-triangle charts (grown to own a 1K texel), charts smaller than a few 1K texels are grown, and re-packs use the smallest padding that keeps 4 px at 1K (`mesh.uv.maximumRepackRounds`, default 10). Gutter and sub-texel audits label re-packed charts by shared UV vertices, as xatlas groups them. Useful2K coverage must reach30% (`mesh.uv.minimumCoverage`). The4 px 1K gutter floor never relaxes; a dense head whose many small charts cannot reach30% at that gutter may declare a lower floor (at least20%) only with `mesh.uv.coverageReview` `{reviewed:true,notes}`, checked before charting and recorded with the floor in the unwrap and imported-atlas results. Check actual2K/1K raster coverage, overlap, fragmentation and gutters. Every face must own at least one mapped texel at4K. At the derived2K/1K resolutions a measured allowance (`mesh.maximumSubtexelFraction`, default0.5%, at most2%, rounded up to whole faces) admits faces that own no texel only when, under each corner and the centroid, the nearest mapped texel (the colour bake padding copies there) belongs to the face's own chart. Faces over the bound, or sampling another chart, fail and require bounded UV repair; counts and bounds are recorded per resolution. Padding never counts as mapped coverage; source4K maps are also inspected. `reuseReviewedUvs` imports a prior atlas only after audits. Direct `uvMesh` export inputs and historical replay must pass these same imported-atlas audits before native preparation; successful results pin the UV audit evidence. Reject mismatches and retain failed receipts. A UV-only pass must not silently change the mesh.
6. **Bake:** before sampling, approve `approval.appearanceField` with the exact `fieldSha256` and the active geometry input role/hash (`uvMesh`, otherwise `repairedMesh`, otherwise `comfyExport`, otherwise the Pixal `raw` shape). This binds the saved appearance field to the geometry it was generated for; a missing, pending or mismatched approval stops the bake. `bake` samples the real six-channel saved appearance on final UV surface positions at4K, in65536-sample CPU chunks, four workers. Decoder overshoot needs explicit `allowDecoderOvershoot`; clipping happens **after** interpolation and is counted. Report nearest-field fallback counts. Fill **unmapped padding only**; preserve opaque black pupils/dark hair. Produce2K and1K with BOX filtering, keep actual surface coverage separate from padding. View all atlas images and mapped features; high fallback counts are a review concern, not automatic approval.
7. **Paint (optional):** when the manifest has a `paint` section, `paint` applies its `operations` in order to the 4K bake (or a reviewed imported `basecolor4k`) and becomes the colour source for ownership rules and tone. A `crest` operation selects raised midline faces in 3D: face centroids within `midlineHalfWidth` of the lateral midline, inside `angleRange` around a pivot at `pivotHeight` of the bounding box (0° straight back, 90° up), and more than `envelopeClearance` of the height outside a skull envelope (minimum pivot radius per `angleBinDegrees` × `slabWidth` bin). It then grows into edge-adjacent light-gray faces (`grow`), using position-welded adjacency because UV seams split vertices, and repaints only untextured texels (not darker than `preserve.darkBelow` or redder than `preserve.redAbove`) with `color` plus seeded grain, and the central `stripeHalfWidth` faces with `stripeColor`. A `fill` operation paints faces chosen by a face condition (`index`, bbox-relative centroid `x`/`y`/`z`) over their own texels and the padding nearest them, with a literal colour or `{"median": condition}` of other mapped texels. Each operation emits a 4K face mask (`<name>-faces-4096.png`; crests also `<name>-stripe`) for review and for ownership rules; the stage writes 4K/2K/1K BOX maps and `paint.json`. [examples/texture-rules.json](../../tools/headkit/examples/texture-rules.json) holds the worked troll-male-01 sections. Review the recolored atlas and every mask on the model; missing or rejected review blocks ownership, tone and everything after.
8. **Ownership:** supply reviewed discrete0..9 atlas masks or use `ownership` with calibrated view masks, a4×4 view-projection matrix and camera origin per view. Projection uses floating triangle visibility through Embree, not an8-bit vertex depth map. Unknown mapped texels remain failures, never automatic hair. Calibrate and inspect hairline, ears, foreground hair, horn roots, tusks and implants at front and both sides. Separate ownership from RGB; imported atlas and view masks must be eight-bit `L` images. RGB, palette-indexed and higher-bit masks are rejected before reading labels in projection, tone matching, quantization and native export. Channel IDs use nearest selection, never numerical blending. Imported1K/4K masks require `ownership.reviewed: true` and `ownership.sourceSha256` matching the exact active UV mesh, including direct tone, palette and runtime-shade export paths. When `uvMesh` is not imported, their receipts depend on the approved `unwrap` output so later UV changes or review rejection invalidate reuse. If only a reviewed 1K mask is supplied, the tone stage expands it to 4K with nearest-neighbor filtering after validating an eight-bit L image with labels 0..9; the source and expanded-mask hashes are recorded in the receipt. Review the 1K edge limitation. A 1K mask may also be used directly for palette quantization and native export.
   `ownership.mode: "rules"` labels texels from data instead: `regions` name reusable conditions and `rules` is a priority list (first match wins, unmatched mapped texels take `default`, padding takes the label of the nearest mapped texel). Conditions combine `all`/`any`/`not`, `region`, `mask` (a paint mask), `mapped` and comparisons `{"of": Q, "center"?: c, "gt"|"lt"|"ge"|"le": v}` over bbox-relative face-centroid `x`/`y`/`z` (with `center`, the distance from it) and texel colour `r`, `g`, `b`, `lum` (RGB mean), `sat` (max−min), `red` (r−max(g,b)), `rb` (r−b) and `metallic` (baked, or a reviewed imported `metallic4k`). Rules read the paint output and masks when `paint` is configured. They are bbox-relative data, so `ownership.reviewed: true` is required but no mesh hash; the stage receipt and its visual review bind the exact output. The receipt counts texels per rule; inspect `ownership-preview-1024.png` and the isolated channels.
9. **Tone:** `tone` matches **original generated skin and hair separately** to reviewed clean reference sample boxes using bounded logit shifts. Retain texture variation and baked shading, protect accessory layers. The source color must be actual 4K; ownership may be a reviewed 4K mask or a recorded nearest-neighbor expansion of a reviewed 1K mask. The tone output is validated at 4K before deriving 2K/1K; smaller imported color maps are rejected. Review generated-reference medians, edges and gradients. The method does not guarantee perfect local complexion matching, and an incorrect semantic mask cannot be fixed by a color shift. Full face/multiview reprojection is outside this default toolkit; a small failed feature should be a bounded reviewed exception, not an inherited sequence of eye/temple repair scripts.
   Without a detail reference, `tone.mode: "adjust"` applies reference-free per-channel `operations` to the paint (or bake) colour: `set` writes a literal colour where a condition (which may test `channel`) holds; `paletteRamp` keeps each selected texel's brightness and takes its hue from stock palette row `row` of the channel named by `palette` (nearest `luminanceScale`×brightness). Conditions read the input colour and ownership. No operations is an explicit pass-through, still reviewed. This gives `bake → paint → ownership(rules) → tone(adjust) → palette → export` without a reference image.
10. **Palette:** `palette` uses explicit stock palette images and rows for each mapped channel. `rows: "auto"`, or `"auto"` for single channels, picks the lowest-error row by exact ranking: count-weighted mean squared RGB distance of every pixel to its nearest eligible shade, on unique colours, with rows pruned once a partial error exceeds the current top results (about 1 s for a 1K troll head; the brute-force search took about 10 minutes). The resolved rows and the top four per channel are recorded in `row-ranking.json` and the receipt. The lowest error is not automatically the right look. Review alternatives in game and pin an explicit row when another is preferred. Default skin/hair0/1; valid hardware2/3,cloth4/5,leather6/7,tattoo8/9 may be used intentionally for accessories (e.g. horns/tusks8, cybereye9). Reject transparent palette entries and shade255. Native export also rejects imported shade maps unless they are 1K eight-bit grayscale with every shade below255. Inspect decoded1K texture, each isolated channel and alternate character palette selections. Confirm stock neck skin-shade matching; a bounded recorded `shadeOffsets` correction is allowed. Nearest-colour shade indices sit wherever the chosen row happens to match the bake (measured on troll heads 015-020: skin medians 40-200 against 68-122 on stock heads), so every other in-game row reads too dark, too pale or flat. Opt-in `toneMatch`, for example `"toneMatch": {"0": {"reference": "troll-male-skin-v1"}}`, remaps that channel's shades by luma rank (ties share a shade, brighter never maps darker) onto a measured stock distribution from the committed `tools/headkit/stock-shades.json` (101-point mean quantile function of the stock `pmg0_head001`-`013` PLTs, sources pinned by SHA-256; `troll-male-hair-v1` is also measured). Skin references exist for every metatype and sex (`human-`, `dwarf-`, `elf-`, `orc-` and `troll-` with `male-skin-v1` or `female-skin-v1`), measured from each prefix's keys-only stock PLTs. Add one with `run_headkit.py shade-reference --name NAME --layer N --description TEXT --plt STOCK.plt...`: it appends the quantiles and every source's resref and SHA-256 without rewriting existing entries. It replaces `shadeOffsets` for that channel and leaves other channels byte-identical. With `"auto"` the row is chosen after matching, as the row that best shows the bake with the matched shades; an explicit row is kept. With `"rowFrom": "design"` in the channel's `toneMatch` entry (bootstrap route), the `"auto"` row instead follows the design image. The stage projects the 1K ownership atlas to a front view of the UV mesh and registers it on the design silhouette (the backdrop matte, `matte.backgroundTolerance`). It takes the design's mean Lab colour inside the eroded channel, and picks the usable row whose decoded mean colour is closest, with lightness at 0.25 weight because the matched shades already set lightness. `design-reference.png` shows the registered design beside the channel overlay. The receipt records the design colour, the top rows with their distances and the bake-referenced row (`designRow`). Below 200 design pixels in the channel, it keeps the bake row and records why. On the 20 troll heads with hand-pinned skin rows, the design row was closer to the pin than the bake row on 16, with median Lab distance 5.4 against 10.6. That takes about 4 s per head. Hair and tattoo channels stay bake-referenced: on those pins the bake row was closer. Use `rowFrom: "design"` for skin on new bootstrap heads. The receipt records per-channel before/after shade statistics, the reference percentiles and file pin, the colour error before matching and the best rows for the matched shades (`rowsAfter`). Matching is texel-weighted over the atlas, so review the decoded result in several rows and in game. Review skin beneath cyberware and ears/hairline, not just front appearance.
11. **Fit/export/native:** supply measured positive similarity landmarks in NWN basis, or a reviewed matrix bound to the exact source SHA. GLB→NWN basis is`(x,-z,y)`. Use per-head neck contact, forward resting angle and reserved resref; donor coordinates are never defaults. `export` writes one PLT and plain rigid ASCII head. `native` compiles the binary MDL through Blender 5.2 and the Neverblender add-on (its bundled cleanmodels compiler, PhenoMorpher's `neverblender_mdl.compile_folder`, headless, one process) when the head has the local compiler binding `mdl-compiler.json` beside `bindings.json` (`{"blender": {"path", "sha256"}, "neverblender": {"path"}}`; machine paths, never a portable lock). The binding sits outside `bindings.json` because the bindings hash binds every stage; only the native branch reads it, so adopting it stales export/native only. `inputs` declares the binding, the Blender executable and the add-on tree for native launches, and `native.json` records the compiler identity (Blender version, Neverblender version, cleanmodels release, compiler hash), the compile receipt and the engine files. Without the binding, native falls back to the EE client's `compilemodel` in an isolated user directory (kept so earlier receipts replay). Either way it uses the maintained armor fixed-string-tail sanitizer, proves other bytes/decoded corners/normals/UVs unchanged, and produces a verified MDL+PLT-only HAK. No unsupported material textures are packaged. In-game palette, fit and appearance approval remain mandatory and separate.

`render` uses Blender CPU, four threads, matching clay/color-only/material-lit views with actual UV textures and no added AO. The anatomical front angle is a measured manifest input. Default cameras cover front, both profiles, both three-quarter views, back, crown, actual underside, face/ears and cyberware; adjust close-up targets as data when an accessory lies elsewhere. Render2K inspection sheets/atlases and actual1K viewing-distance previews. The processing example sets `render.sizes` to `[2048, 1024]`, also the default. Each size renders all selected cameras and all three materials with the same framing and lighting. The 1K pass uses actual BOX-filtered 1K textures, not resized 2K screenshots. Outputs live under `renders/2048/` and `renders/1024/`, with per-material view folders, native-resolution labeled `*-sheet.png` contact sheets, and full-resolution base-color/roughness/metallic/opacity images under `atlases/`. Atlas sources must be at least the requested resolution; the renderer rejects upsampling. A single explicit `render.size` remains available only when `diagnostic: true`; otherwise it is rejected, and it does **not** satisfy delivery review. A render receipt records timings, dimensions, atlas and sheet hashes but never a visual pass.

## Resume, limits and delivery

Each CPU attempt has an intent, immutable receipt, input/output hashes, code version, elapsed time and preserved diagnostics. Every CPU stage requires an explicit `review --stage STAGE --decision approved --notes TEXT` before its output can feed downstream processing. Inspect the stage's emitted evidence/files first; numerical completion is not approval. The current decision is stored in runner state as a hash-pinned immutable review bound to that exact stage receipt. Missing/rejected/stale approval blocks consumers, including cached downstream outputs and native packaging. A rejected stage can be inspected and reviewed again without recomputing it; old decisions remain preserved. `status` reports numerical completion separately from pending/approved/rejected review. Imported pinned checkpoints remain an explicit operator-selected entry point, not an approval of earlier stages.

A completed stage is reused only while manifest, bindings, code, dependencies and outputs still match. Freshness is stage-scoped: a receipt binds only the manifest sections (or single keys, such as prepare's `approval.referenceDesignReviewed`) and input roles its stage closure reads, and only the code its stage imports. `runner.py` is bound per stage as a slice without the other stages' `_execute` branches, so an edit inside one stage's branch stales that stage only; edits to shared runner code, `common.py` or shared tooling stale every stage. A stale stage is reported by name before its input pins are checked. Tone binds only `palette.inputs` (the palette images its ramps read), so pinning a palette row stales palette, not tone. A rerun whose outputs are identical to an approved attempt (binary SHA-256; JSON equal after normalising attempt folders and dropping `*Seconds`) carries that review; anything else needs a new review. `chain` skips stages the manifest leaves out (`paint`, `render`) and a pass-through `tone` (no operations; palette then reads the paint or bake colour). No per-head Python is required. After two failures on the same manifest/code, stop and prepare an exception with exact scope; do not relax gates or keep looping. A transient GPU dispatch failure is reconciled, not retried blindly.

Initial extraction supports static single-primitive identity-node GLBs in the normalized Pixal coordinate frame. Unsupported transforms, skins, extensions and multiple primitives are rejected explicitly. New races/styles and unreviewed geometry are trials; replaying two accepted Troll assets establishes transport/packaging evidence, not an autonomous factory across arbitrary heads. See [validation evidence](headkit-validation.md).

For `replay`, every consumed `source`, `shades`, `layers`, `binary` and `expectedPlt` path must have a matching input SHA256 pin. Replay resolves aliases before processing, rejects missing/conflicting pins, uses those resolved paths and verifies the frozen pins again before writing successful replay evidence. The receipt records the exact consumed role bindings.

Deliver pinned raw/exported/final meshes, generated appearance, final atlases and actual1K PLT, clay/textured views, isolation overlays, numeric defects, review decisions, native proof and a resume checkpoint. Keep all historical failures. User approval of in-game inspection is required before promoting a new candidate; generation success, numerical checks and rendering do not confer that approval.

Render plans require nonempty camera and material-mode lists. Every requested size/mode/camera combination must produce exactly one frame before the render stage can succeed; empty or incomplete plans cannot be approved as inspection evidence.

## Client trial module

`tools/heads/build_head_trial.py --spec SPEC.json --output DIR` packages finished native heads (each head's `native` stage folder, or declared resources) into one top-priority trial HAK and an isolated client test module, with `Launch.cmd` and a hash-checked `runtime-manifest.json`. The spec names the base HAKs and module (SHA-256 pinned), the identity, and per head its slot model, skin/hair rows, tattoo rows and metal row. Actors are female for a `pf*` prefix and male for `pm*`; `prefix` may list one race's families (for example `["pmh0","pfh0"]`) so its male and female heads share one module, each actor taking its head's gender. The base module's actors must match the identity unless `base.actorIdentity` declares the body they were built for (for example the male troll fixture module as the template for female troll heads on the release body, appearance 15104); the base HAKs must then supply that identity's body. A trial holds at most 8 heads; split a larger batch into several trials. Actors spawn from blueprints one head row at a time and stand still for inspection: trial blueprints drop the fixture's heartbeat animation cycle (walk, cast, attack) and are plot, so a stray click cannot start combat; the spawn script that logs slots and colours stays. With `"motion": true` in the spec, actors instead keep the fixture's cycle (pause, talk, walk, run, cast, attack, crouch, worship, death) and revive 10 s after death, for idle-and-motion client checks. On entry a sweep shows every head for 5 s, then chat commands `next`, `prev`, `head N` and `sweep` switch rows. To inspect, walk past the row on open ground (never click an actor), turn the camera to face it, tilt with Page Down and zoom only about halfway. Launch it through the shared-tool launcher with the exact consumed inputs: `build_head_trial.py --spec SPEC.json --inputs LIST.json` writes them (the spec, base HAKs and module, and per head `native.json`, the HAK and the converted ASCII model, or the declared resources) for `--input-path-list`. After a client run, `tools/heads/verify_head_trial.py --manifest DIR/runtime-manifest.json` checks every actor's `HEAD_FIXTURE_SLOT`/`COLORS` and that every head row was shown. A passed log check proves slots and rows, not the look; the in-game review is still the user's.

## Running a head batch

Lessons from the 20-head troll batch v2 (2026-10-25), where one orchestrator dispatched one CPU agent per head. Each rule answers a mistake that actually happened.

- **Design pick.** Two horns only. Each horn must be short and thick and form ONE continuous curve: zoom on each horn and reject any extra ring, coil, prong or branch. Ram loops must stay fully visible beside the head; a loop that wraps behind the ear came back from Pixal as a tall horn plus a separate coil. Short horns curving up and back are the most reliable shape. Hair must be a mass that covers the scalp, with nothing below the jaw. Sparse slicked-back strands left the occiput open on every seed of one design, and large horns swept over the head with layered hair made a shape decode that exceeded a 12 GiB card at every seed.
- **Attempt cap (user rule).** At most 5 geometry submissions per head slot (reseeds, OOM failures and redesigns all count) and at most 3 designs. At the cap, stop and report the slot with its best candidate; the user decides.
- **Check the raw shape right after geometry, before appearance** (`run_headkit.py check-occiput RAW.glb ...`, read-only, `occiput.py`). Look for an open back of skull: face area per height band in the central back third, OPEN when two adjacent bands between 35% and 80% of the height hold under 5% of the median band. An open shape gets one automatic geometry reseed (+1000, calibrate reused); open twice means change the design. Agents still confirm the back and the horn pieces on their precluster, and stop with `GEOMETRY: open back of skull` or `HORNS: extra piece`. A detached small accessory on a good horn (a stray ring) is removed by a reviewed tight shell selection in repair, not by another re-roll.
- **Sharing one GPU between designs and Pixal.** A design queued behind Pixal jobs hits `design`'s dispatch deadline (default 2700 s; `design --deadline SECONDS`, or `--front` to queue ahead of pending prompts), and Flux.2 left in VRAM makes the next shape decode run out of memory. Hold new Pixal submissions while a design runs, start the design on an empty queue, and unload models (ComfyUI `/free`) after it. Free models before every Pixal job; after an OOM, retry once after freeing, then reseed geometry once. Other processes (an open game client, other sessions) also hold VRAM.
- **Re-roll bookkeeping.** Key dispatch by head plus GPU ready time, not head name, or a re-roll under the same name is never picked up. Relink `inputs/raw.glb` and `field.npz` when the GPU output changes. Give every design launch a frozen copy of the spec: editing the master spec mid-launch invalidates it.
- **Agent loop budget.** Settle the neck cut and stray shells by dry run before the first repair. Allow repair at most 3 launches, each fixing every refusal reason; ownership 2; tone and palette 2 each, with all pins chosen from one decoded comparison sheet; render 1 (+1 after a later pin); and a 2.5 h cap per head. Every launch hashes about 3,650 inputs (about 1.5 GB) twice: always chain an approval into the next stage and never run approve-only launches. The orchestrator's acceptance is the render approval. Helpers must exit by themselves; kill stray ones. With these rules a head took about 1 h, against 2-3 h before.
- **Toolkit edits during a batch.** Design launches pin the whole headkit tree and CPU stages pin their closures. Before changing toolkit code, wait for running design launches and freeze the CPU slots so no stage launch spans the edit. Keep native-only changes inside the runner's native branch and outside `bindings.json`, so finished stages stay fresh.
- **Recompiles and other multi-head stage runs: one launch.** `run_headkit.py batch --heads HEADS.json --stages export` (HEADS.json: a list of `{"manifest", "bindings", "run"}`) runs `chain` for every head in one launcher launch. Build its input list with `inputs --heads HEADS.json --stages export,native`. After checking each export matrix against its reviewed fit, `batch --heads HEADS.json --approve export --notes "..." --stages native` records each head's approval and compiles every eligible head in one headless Blender run (`native.precompile`: PhenoMorpher `compile_folders`, one folder and one compile receipt per head). Each head's native stage then reuses its binary only when the compiler, sources and lookups are identical, still runs its own decode audit, and records the shared compile receipt as `compiler.precompiled`. Receipts, reviews and locks stay per head, and one head's failure is reported in its row without stopping the others. If the shared compile fails, those heads compile one by one. On the 10 batch-1 heads the binaries were byte-identical to per-head compiles, and the compile plus packaging took 88 s against 136 s. With the hash cache warm, one launch for all 10 heads froze and verified its about 3,050 inputs in 18-23 s, about the same as a single-head launch (78-120 s without the cache). Ten heads' export and native went from 20 launches to 2. Set `SRN_LAUNCH_HASH_CACHE` (see `docs/shared-tooling-and-workflow.md`) for head launches. Since #63 changed `launch_shared_tool.py`, launches need a fresh migration receipt.
- **Body neck input.** Decompile the body skeleton and neck part with PhenoMorpher `mdl-decompile` (Blender 5.2 + Neverblender), then run `python -m headkit.body_neck`.
